## Context

本项目为全新工具，无现有代码约束。用户需要在淘宝限量抢购/秒杀场景中以毫秒级速度完成下单。人工操作延迟在秒级，自动化工具可显著提高成功率。项目为 CLI 形态，技术栈选择 Node.js + Playwright。

## Goals / Non-Goals

**Goals:**
- 提供浏览器自动化下单（详情页 + 购物车两条流程）
- 提供无脑连点式重试机制（200ms 间隔 / 30s 窗口 / 不检测DOM）
- 提供 API 直调下单作为高速替代方案（通过浏览器抓包逆向参数）
- 提供手动登录 + 自动提取 cookie 的凭证持久化管理
- 提供定时触发，设定目标时间后自动准备并在到点瞬间执行
- 支持 YAML 配置文件 + CLI 参数覆盖

**Non-Goals:**
- 不做多账号并发抢购
- 不做商品库存监控/预约提醒
- 不做 GUI 图形界面
- 不破解淘宝签名/加密算法（API 模式依赖浏览器抓包还原参数）

## Decisions

### 1. 技术栈：Node.js + Playwright

Playwright 对反检测支持更好（自动隐藏 webdriver 特征），API 设计现代，事件驱动模型适合连点器性能要求。

替代方案：Python + DrissionPage — 开发快但连点器性能不如 Node.js 的事件循环模型。

### 2. 双模式架构共享认证层

浏览器模式和 API 模式共享 Session Store，各自独立实现下单逻辑。浏览器模式用 Playwright 操作 DOM，API 模式用 axios 发 HTTP 请求。通过 CLI 参数 `--mode browser|api` 切换。

### 3. 重试策略：无脑点击 + 固定间隔

不与 DOM 交互进行状态检测，直接循环点击。检测 DOM 状态有时间差，不如无脑点击。200ms 固定间隔 = 每秒 5 次，30 秒窗口内 150 次尝试。保持固定间隔不做退避——因为秒杀窗口极短。

退出条件：
- 页面 URL 变化（跳转到成功页/订单详情）→ 成功退出
- 页面出现终局文本（售罄/下架）→ 失败退出
- 检测到登录过期 → 失败退出
- 超时窗口过期 → 失败退出

### 4. 配置存储：YAML + CLI 覆盖

商品信息、重试参数、定时触发时间通过 YAML 配置文件管理。CLI 参数优先级高于配置文件。

### 5. 认证方案：手动登录 + Cookie 持久化

用户在 Playwright 打开的浏览器窗口中手动完成登录（包括验证码），工具自动提取 cookie 存储到 `~/.taobao-tool/credentials/<profile>.json`。支持多 profile。

### 6. API 逆向路径

浏览器模式下开启 Playwright 网络拦截，记录下单流程中的所有 HTTP 请求。分析请求参数，区分固定参数和动态签名参数，然后尝试还原请求构造逻辑。如果签名参数可还原则实现 API 模式，否则 API 模式降级为不可用。

### 7. 定时触发

用户设定目标时间，工具计算提前量（浏览器模式下约需 3-5s 导航时间），自动提前启动并在目标时间瞬间发起首次点击。使用 `setTimeout` 精确到毫秒级触发。

## Risks / Trade-offs

- **[风控风险]** 高频请求可能触发淘宝反爬机制 → 提供可配置的请求频率上限，API 模式强制最小 100ms 间隔
- **[接口变更风险]** 淘宝 UI 选择器和 API 参数可能变更 → 选择器通过配置文件管理，API 参数模板化
- **[验证码风险]** 高频率操作可能触发验证码 → 浏览器模式遇到验证码时暂停并提示用户手动处理；API 模式相对不易触发
- **[API 逆向不确定性]** 淘宝接口签名可能无法完全还原 → API 模式为可选功能，浏览器模式独立可用

## Open Questions

- 定时触发模式下浏览器提前多长时间启动合适（取决于网络和页面加载速度）？
