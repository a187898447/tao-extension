## Context

现有工具的核心假设是"用户已知商品 URL"，通过 `navigateAndSelectSku(productUrl)` 直接导航。但定时上架场景下，商品链接在上架时刻才首次出现在店铺搜索结果中，此前不可用。

本设计在现有浏览器自动化流程前端插入一个"店铺搜索发现"阶段，将完整的定时上架流程拆为：店铺搜索 → 结果识别 → 进入商品页 → 现有下单流程。

## Goals / Non-Goals

**Goals:**
- 支持用户配置店铺 URL + 搜索关键词 + 价格区间来替代显式商品 URL
- 工具提前在搜索框预填关键词，在目标时间前开始轮询搜索，从结果中发现目标商品
- 识别到商品后无缝切入现有下单流程（跳过 SKU 选择，默认第一个规格）
- 与现有定时触发调度器集成，不破坏原有 productUrl 模式

**Non-Goals:**
- 不做多关键词或复杂搜索结果排序
- 不做商品图片识别匹配（只用价格区间）
- 不做跨店铺搜索或淘宝全局搜索
- 不改变 API 模式（本功能仅浏览器模式）

## Decisions

### 1. 搜索流程：预填 + 轮询

工具提前导航到店铺首页，找到搜索框并预填关键词（不触发搜索）。在 `targetTime - searchLead` 时刻开始循环：点击搜索 → 等待结果加载 → 检测目标商品。未找到则刷新/重新搜索。

**替代方案**：每次重新导航到搜索结果 URL（`storeUrl/search?q=keyword`）。放弃原因：淘宝店铺搜索可能用 POST，且有 CSRF/token 参数，不如模拟真实点击稳健。

### 2. 商品识别：新品筛选 + 价格匹配

搜索结果加载后，优先找到"新品"筛选标签并点击，然后在筛选后的结果列表中按价格区间匹配。价格用元素文本中提取的数字在 `[min, max]` 范围内即视为命中。

**替代方案**：标题关键词匹配。放弃原因：关键词可能不精确、商品标题可能变化。价格区间更稳定。

### 3. 跳过 SKU 选择

定时上架商品通常默认只有一个规格，进入商品页后直接点击"立即购买"，不执行现有 `selectSku` 流程。通过配置 `sku: null` 或新增 `skipSku: true` 触发。

### 4. 与调度器集成方式

在 `schedulePurchase` 的 `prepare` 阶段，根据 `listingType` 分流：
- `normal`（默认）：现有逻辑，直接 `navigateAndSelectSku(productUrl)`
- `scheduled`：走新流程 `searchStoreAndFindProduct(storeUrl, keyword, priceRange)`

`prepare` 返回一个统一的 `{ page, submitClicker }` 供 `execute` 使用，接口不变。

## Risks / Trade-offs

- **[页面结构变更]** 店铺搜索框、新品筛选标签的 DOM 结构可能变化 → 选择器通过 `selectors.yaml` 配置化
- **[搜索无结果]** 商品未按预期上架或延迟上架 → 设置 `searchTimeout`，超时后报错退出
- **[风控]** 高频搜索请求可能触发验证码 → 搜索轮询间隔不宜过短（默认 500ms），可配置
- **[误匹配]** 价格区间可能匹配到其他商品 → 后续可扩展标题关键词作为辅助匹配，首版仅价格区间

## Open Questions

- `searchLead` 默认值设为多少合适？（建议 5000ms，可根据实际情况调整）
- 搜索轮询间隔？（建议 500ms）
- 是否需要支持"搜索结果页直接点击"而不进商品详情页（即搜索结果页直接有购买按钮）？
